# JICHINI

> AI 기반 사회초년생 고민 공감 및 유사 고민 사용자 매칭 채팅 플랫폼

JICHINI는 타지역 취업이나 자취를 시작하며 직장생활, 인간관계, 외로움 등 다양한 고민을 겪는 사회초년생이 AI 챗봇에게 고민을 털어놓고, 비슷한 고민을 가진 사용자와 연결될 수 있도록 돕는 소셜 케어 웹 서비스입니다.

연애나 데이팅 목적이 아닌, 비슷한 고민을 가진 사람들과 가볍게 이야기하며 정서적 안정과 현실적인 공감을 얻을 수 있는 서비스를 목표로 합니다.

## 기획 배경

특성화고, 마이스터고 학생들을 비롯해 어린 나이에 타지역으로 취업하거나 자취를 시작하는 사회초년생은 기존 인간관계와 멀어지고 낯선 환경에 적응해야 하는 상황을 자주 겪습니다.

하지만 힘든 감정을 바로 털어놓을 수 있는 공간은 부족하고, 기존 커뮤니티는 관계가 형성되기까지 시간이 오래 걸리며, 연애 앱은 목적 자체가 다르다는 부담이 있습니다.

JICHINI는 이러한 문제를 해결하기 위해 AI 챗봇을 통한 안전한 고민 수용과 유사 고민 사용자 매칭을 제공하여, 사용자가 혼자 고민을 쌓아두지 않고 비슷한 경험을 가진 사람과 자연스럽게 연결될 수 있도록 설계했습니다.

---

## 핵심 가치

- **공감 중심**: 판단하거나 단정하지 않는 대화 경험
- **안전성**: 고민 원문은 기본 비공개, 공유는 사용자 동의 기반
- **현실성**: AI 답변에서 끝나지 않고 실제 사람과 연결
- **부담 없음**: 연애, 성과, 평가 목적이 아닌 고민 공감 중심

```text
사용자 고민 입력
        ↓

        ↓
사용자 매칭 모달 확인
        ↓
상호 동의 기반 1:1 채팅 연결
```

## 주요 기능

### 1. 회원가입 및 사용자 정보 입력

사용자는 회원가입 후 직업, 거주지, 나이, 현재 기분, 고민 유형, 상세 고민을 입력할 수 있습니다.

입력된 정보는 이후 사용자 매칭과 프로필 정보 구성에 활용됩니다.

### 2. AI 챗봇 고민 대화

메인 화면에서 고민을 입력하면 챗봇 화면으로 이동하여 AI와 대화를 이어갈 수 있습니다.

AI는 사용자의 고민을 공감하는 방향으로 응답하고, 진단이나 치료처럼 느껴지는 표현은 지양하도록 설계했습니다.

### 3. 유사 고민 사용자 매칭

AI 응답에서 유사 고민 사용자가 발견되면 매칭 카드가 표시됩니다.

사용자는 매칭 모달을 통해 상대의 지역, 고민 유형, 상세 고민을 확인하고 대화를 신청할 수 있습니다.

### 4. WebSocket 기반 1:1 실시간 채팅

매칭된 사용자와는 별도의 채팅방에서 실시간으로 대화할 수 있습니다.

STOMP 기반 WebSocket 통신을 활용해 메시지 송수신, 읽음 처리, 안 읽은 메시지 알림을 구현했습니다.

### 5. 조언 내역 조회

이전에 대화를 나눴던 사용자 목록을 확인하고, 기존 채팅방으로 다시 진입할 수 있습니다.

채팅방별 안 읽은 메시지 수를 표시하여 사용자가 놓친 대화를 확인할 수 있도록 구성했습니다.

### 6. 내 정보 관리

사용자는 내 정보 페이지에서 프로필 이미지, 이름, 직업, 거주지, 나이, 감정 상태, 고민 정보를 수정할 수 있습니다.

수정된 정보는 이후 매칭과 사용자 프로필에 반영됩니다.

## 프론트엔드 구현 포인트

### 컴포넌트 기반 화면 구성

로그인, 회원가입, 메인, AI 챗봇, 채팅방, 내 정보 페이지를 화면 단위 컴포넌트로 분리하여 React 기반으로 구현했습니다.

각 페이지는 독립적인 상태와 UI 역할을 가지도록 구성했고, 사용자 흐름에 따라 React Router로 페이지 이동을 처리했습니다.

### 메인 화면 첫 메시지 흐름

메인 화면에서 입력한 고민이 챗봇 화면으로 자연스럽게 이어지도록 첫 메시지 전달 흐름을 설계했습니다.

페이지 이동 시 컴포넌트 내부 state가 초기화될 수 있기 때문에, 챗봇 화면 진입 시 서버의 대화 히스토리를 조회해 기존 대화 내용을 다시 렌더링하는 구조를 구성했습니다.

### 실시간 채팅 클라이언트

SockJS와 STOMP Client를 활용해 WebSocket 연결을 구성했습니다.

채팅방 구독, 메시지 발행, 안 읽은 메시지 알림 구독, 읽음 처리 요청을 프론트엔드에서 관리하여 실시간 대화 경험을 구현했습니다.

### CSS Module 기반 스타일 관리

초기에는 전역 CSS 클래스명을 사용했지만, 페이지가 늘어나면서 클래스명 충돌 가능성이 생겼습니다.

이를 해결하기 위해 CSS Module을 적용하여 컴포넌트별 스타일 범위를 분리하고, 유지보수하기 쉬운 스타일 구조로 개선했습니다.

## 실행 방법

### 1. 저장소 클론

```bash
git clone https://github.com/JICHINI/frontend.git
cd frontend
```

### 2. 패키지 설치

```bash
npm install
```

### 3. 환경 변수 설정

프로젝트 루트에 `.env` 파일을 생성하고 API 서버 주소를 설정합니다.

```bash
npm run dev
```

### 5. 빌드

```bash
npm run build
```

## 안전성 및 윤리적 고려

JICHINI는 의료 행위나 전문 심리 상담 서비스를 대체하지 않습니다.

AI의 답변은 사용자의 고민을 정리하고 참고용 조언을 제공하는 목적으로만 사용되며, 진단이나 치료를 목적으로 하지 않습니다.

또한 사용자의 고민 원문은 기본적으로 비공개이며, 매칭에 활용되는 정보는 사용자가 동의한 요약 정보와 프로필 기반으로 제한하는 것을 목표로 설계했습니다.

---

## 배운 점

첫 팀 프로젝트에서 팀장으로 프론트엔드와 디자인을 담당하며, 단순히 화면을 구현하는 것보다 화면 구조, 스타일 범위, 상태 흐름을 먼저 설계하는 것이 중요하다는 것을 배웠습니다.

또한 기획 단계에서 팀원 간 요구사항과 API 응답 구조에 대한 이해가 충분히 맞춰지지 않으면, 후반 개발과 API 연동 과정에서 화면 흐름과 데이터 처리 방식이 어긋날 수 있다는 것을 경험했습니다.

전역 CSS 클래스 충돌과 페이지 이동 시 state가 초기화되는 문제를 해결하며, 이후 프로젝트에서는 기능 구현 전에 사용자 흐름과 데이터 흐름을 먼저 정리하고 유지보수하기 쉬운 구조를 고민하는 방식으로 개발하게 되었습니다.
